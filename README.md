## Часть 1. Теория

### 1. Что такое СУБД?

- СУБД - это программа, которая позволяет работать с базой данных. Можно добавлять, удалять, изменять и искать информацию.

- В Excel тоже можно хранить данные, но когда информации становится много, удобнее использовать базу данных. Особенно если с ней работают сразу несколько человек.

- Базы данных бывают разные:
    - Реляционные - PostgreSQL, MySQL. Хранят данные в таблицах.
    - Документные - MongoDB. Хранят данные в документах.
    - Ключ–значение - Redis. Данные хранятся по ключам.
    - Графовые - Neo4j. Используются, когда между данными много связей.

    В реляционной базе данные находятся в таблицах. Строка — это одна запись, а столбец — какая-то информация о ней. Например, ID клиента, его имя или телефон.

### 2. Первичный и внешний ключ

- Первичный ключ (PRIMARY KEY) — это уникальный номер записи. 

  Внешний ключ (FOREIGN KEY) нужен, чтобы связывать таблицы. 

- Связи бывают трёх видов:

    - Один к одному - один человек и один профиль.
    - Один ко многим - у одного клиента может быть несколько счетов.
    - Многие ко многим - студент может учиться на нескольких курсах, а на одном курсе может быть несколько студентов. Для этого создают отдельную таблицу связей.

### 3. Нормализация

- Нормализация нужна, чтобы не повторять одни и те же данные в разных местах.

    - Есть три основные нормальные формы:

        - 1НФ - в одной ячейке должно быть одно значение.
        - 2НФ - данные должны зависеть от всего ключа, если он состоит из нескольких полей.
        - 3НФ - поля должны зависеть от ключа, а не друг от друга.

- Денормализация - это наоборот, когда мы специально повторяем некоторые данные, чтобы быстрее получать информацию.

### 4. SQL

- WHERE нужен, чтобы отбирать строки по условию. HAVING делает примерно то же самое, но уже после группировки.

- Например, через WHERE можно найти счета с балансом больше 1000, а через HAVING - клиентов, у которых больше двух счетов.

- JOIN нужен, чтобы соединять данные из нескольких таблиц.

    - INNER JOIN - возвращает только совпадающие записи.
    - LEFT JOIN - возвращает все записи из левой таблицы, даже если в правой совпадений нет.
    - RIGHT JOIN - то же самое, только для правой таблицы.
    - FULL JOIN - возвращает записи из обеих таблиц.
    - CROSS JOIN - создаёт все возможные сочетания строк.

    Ещё можно соединить таблицу саму с собой. Это называется SELF JOIN.

- Это три запроса для удаление данных или таблиц

    - DELETE - удаляет строки, можно указать условие WHERE.
    - TRUNCATE - очищает всю таблицу.
    - DROP - полностью удаляет таблицу вместе с её структурой.

 
### 5. NULL, индексы и транзакции

- NULL означает, что значение отсутствует или неизвестно. Это не ноль.

    Например, если у клиента не указан телефон, в поле может стоять NULL.

    Для проверки используют `IS NULL` или `IS NOT NULL`.

- Индекс нужен для ускорения поиска данных. Например, если часто ищем клиента по ID, индекс помогает быстрее его найти. Но индексы занимают дополнительное место и могут замедлять добавление данных.

- Транзакция - это несколько действий, которые должны выполниться вместе.

    Например, при переводе денег нужно списать сумму с одного счёта и добавить на другой. Если что-то пойдёт не так, изменения нужно отменить.

    Для этого есть:
    - COMMIT - сохранить изменения.
    - ROLLBACK - отменить изменения.

    У транзакций есть четыре свойства:

    - Атомарность - либо выполняются все действия, либо ни одного.
    - Согласованность - данные должны оставаться правильными.
    - Изоляция - транзакции не должны неправильно мешать друг другу.
    - Долговечность - после сохранения изменения не должны пропадать.

## Часть 3. Проверка подключения через Python

Для проверки я использовал Python, PostgreSQL и pytest.

Сначала нужно запустить PostgreSQL. Я выбрал вариант через Docker.

Команда для создания контейнера:

`docker run --name intern-postgres -e POSTGRES_USER=intern -e POSTGRES_PASSWORD=intern123 -e POSTGRES_DB=intern_db -p 5432:5432 -d postgres:17`


Дальше нужно создать таблицы. Для этого я подготовил `setup.sql`, а запросы находятся в `queries.sql`.

Загрузить файлы можно командами:

# Копируем файл создания таблиц в контейнер
`docker cp setup.sql intern-postgres:/tmp/setup.sql`


# Создаём таблицы и добавляем данные в базу
`docker exec intern-postgres psql -U intern -d intern_db -f /tmp/setup.sql`

# Копируем файл с SQL-запросами в контейнер
`docker cp queries.sql intern-postgres:/tmp/queries.sql`


# Выполняем SQL-запросы из файла
`docker exec intern-postgres psql -U intern -d intern_db -f /tmp/queries.sql`

### Тест на Python

В `test_db.py` я сделал простой тест.

Он подключается к PostgreSQL, выполняет запрос `SELECT now()` и проверяет, что база вернула текущую дату и время.

Если подключение работает, тест проходит.

Для запуска сначала устанавливаем библиотеки:

`pip install -r requirements.txt`

Запускаем тест:

`python -m pytest -v`

### Проверка неправильного пароля

Также нужно проверить, что будет, если указать неправильный пароль.

`$env:DB_PASSWORD = "wrong_password"`

И снова запускаем тест:

`python -m pytest -v`

В этом случае ожидается `1 failed`, потому что база не должна разрешать подключение с неправильным паролем.

Потом возвращаем правильный пароль:

`Remove-Item Env:DB_PASSWORD`

И запускаем тест ещё раз.
